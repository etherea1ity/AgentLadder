# v0.2 RAG Architecture

This document records the architecture boundary for `learn/v0.2-rag-agent` / `v0.2-rag-agent`.

## Layering

```text
apps/web        React UI, Klara presence, Run Chain cards
apps/api        FastAPI sessions/runs/SSE and local JSONL app storage
src/agent_ladder/core
                generic contracts, runtime helpers, tracing
src/agent_ladder/llm
                provider interface, DashScope/OpenAI-compatible client, token estimates
src/agent_ladder/rag
                v0.2 RAG contracts and algorithms
```

The frontend does not call the LLM or RAG code directly. It consumes API responses and SSE/module events.

The API layer owns session/message/run persistence and invokes the runtime.

The RAG package owns document loading, chunking, indexing, retrieval, reranking, context building, source/citation contracts, routing, and writer prompt construction.

## RAG pipeline

```text
LocalMarkdownLoader
→ OverlapTextSplitter
→ records_from_chunks
→ DashScopeEmbedder
→ LocalIndexStore
→ DenseRetriever + BM25Retriever
→ HybridRetriever
→ SimpleReranker
→ ContextBuilder
→ Klara Writer prompt
→ AnswerFrameV1
```

## Observable modules

Each public step is emitted as a `ModuleResult` so the right-side Run Chain can render cards without exposing chain-of-thought:

```text
Intent Router
Dense Retrieval
BM25 Retrieval
Hybrid Retrieval
Reranking
Context Builder
KlaraAgent Writer
```

Module payloads are structured JSON and can include algorithm names, top-k values, candidate lists, prompt/system input, model, latency, and token counts when relevant.

## Current intentional compromise

`src/agent_ladder/core/runtime/klara_agent.py` currently orchestrates the RAG flow. That is acceptable for v0.2 because it keeps the teaching path short.

Before v0.3 grows agentic loops, the preferred boundary is:

```text
src/agent_ladder/agents/klara_agent.py
# or
src/agent_ladder/rag/runtime/rag_agent.py
```

Then `core` can remain generic while RAG/Agentic RAG orchestration lives above it.
