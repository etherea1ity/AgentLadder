# v0.1 Interaction Spec

## Product frame

Agent Ladder v0.1 is a quiet workspace for learning how an agent runs. The UI is English-only. It teaches `Ask → Answer → RunLog → Trace` without surfacing raw chain-of-thought.

## Primary user journey

1. User opens the app and sees the empty home.
2. User enters a question in the bottom input.
3. If no active session exists, frontend creates a session lazily.
4. Frontend starts a run and inserts a user message plus assistant placeholder.
5. ThinkingInlineBar shows `Queued · Preparing the run...` then `Thinking · Understanding your question...` then `Writing · Answer is streaming...`.
6. Assistant content streams into the message.
7. User may click ThinkingInlineBar to open Run Margin; sending does not open it automatically.
8. On completion, ThinkingInlineBar shows `Completed · <duration> · View trace`.
9. Run Margin completed view shows summary, timeline, run log, and collapsed trace JSON.
10. User can rename or delete the session from the sidebar.

## Empty home

Show only:

- ladder mark
- `From Prompt to Policy`
- `A question becomes a trace.`
- input placeholder `Ask your first question...`
- subtle footer hint `v0.1 Minimal Agent · Ask → Answer → Trace`

No quick-start cards, dashboards, large flow diagrams, or hero illustrations.

## Sidebar interactions

- `New Chat`: closes Run Margin, clears active session, focuses input, does not create a backend session until send.
- Conversation click: loads that session, closes Run Margin, clears selected run.
- Rename: inline/popup edit, calls `PATCH /api/sessions/{id}`.
- Delete: lightweight confirmation popover. Confirm calls `DELETE /api/sessions/{id}`.
- Deleting active session: returns to empty home and clears selected run.

## Chat input

- Enter sends.
- Shift+Enter inserts newline.
- During active run, send button becomes Stop.
- Stop calls `POST /api/runs/{run_id}/cancel`.
- File attachments are not available in v0.1.

## ThinkingInlineBar

- Rendered above every assistant answer.
- It is a `button`, not a decorative div.
- It opens or switches Run Margin to the message's run.
- Re-clicking the same bar keeps Run Margin open; X closes it.
- It shows safe visible activity only, never raw chain-of-thought.

## Run Margin open/close

Open only from:

1. ThinkingInlineBar click.
2. assistant Details action.
3. valid `?run=` query.

Close from X, ESC on supported layouts, or session switch. Closing restores focus to the triggering bar when possible.

## State transitions

| Trigger | activeSessionId | selectedRunId | runMarginOpen | Notes |
|---|---:|---:|---:|---|
| New Chat | null | null | false | lazy draft state |
| Send first question | new session | unchanged/null | false | do not auto-open margin |
| Click ThinkingInlineBar | unchanged | run_id | true | switch selected run if different |
| Switch session | target session | null | false | fetch session detail |
| Delete active session | null | null | false | empty home |
| Run completed | unchanged | unchanged | unchanged | status updates only |
| Run failed | unchanged | unchanged | unchanged | failed state visible |
| Cancel run | unchanged | unchanged | unchanged | message becomes cancelled |

## Edge cases

- SSE disconnect before terminal event: call `GET /api/runs/{run_id}` and reconcile.
- Deleted session detail: backend returns 404; frontend returns to empty home.
- Running run in deleted session: backend emits cancellation and hides session.
- Missing API key: run fails with `missing_api_key`, Run Margin failed view shows stage and message.
